Proposal

      
Four small TUI programs that share one UI kit. Each program has one backend trait with a macOS, a Linux and a mock implementation. The popup window is a thin per-OS wrapper; the TUI itself handles esc, so behaviour is identical on both machines.

      
packages/sysmenu/                 # working name, cargo workspace
  crates/kit/      # theme, widgets (list, modal, toast, gauge, big digits), keymap, event loop, --mock
  crates/net/      # bin net    · Wi-Fi, Ethernet, USB/Thunderbolt, VPN → macos.rs | networkmanager.rs | mock.rs
  crates/bt/       # bin bt     · BtBackend    → iobluetooth.rs | bluez.rs | mock.rs
  crates/sound/    # bin sound  · AudioBackend → coreaudio.rs | pulse.rs | mock.rs
  crates/speed/    # library (+ tiny bin) · Cloudflare speed endpoints, same code on both OSes; net opens it with s
  popup/macos/     # PopupHost.app (Swift): rounded panel + dim layer + embedded terminal
  popup/popup.sh   # `popup net` toggle: Hyprland → ghostty --class; macOS → PopupHost socket

      
Shared by both OSes

      
    
        
  • All UI, keymaps, state handling, error toasts, per-row pending states. Roughly 75% of the code.
    • 
        
  • Speedtest is 100% shared and lives inside Network.
    • 
        
  • Backends push events into the UI; the UI never blocks on a backend. That removes the freeze class of bugs.
    • 
        
  • --mock runs any app with fake data, so the next step after these mockups is the same screens running for real in your terminal.

      1. Modules and packaging
      
One suite, installed in pieces. Every module is its own small binary that works alone in any terminal. A tiny core command ties them together, git-style.

      

        
PackageContainsNeeds

        
          
NAMEDispatcher (NAME net runs NAME-net), NAME popup net, NAME list. On macOS also NAME.app (the popup host).at least one module

          
NAME-netWi-Fi, Ethernet, USB/Thunderbolt, VPN, speedtestnothing

          
NAME-btBluetoothnothing

          
NAME-soundOutput, input, per-app volumenothing

        
      

      
    
        
  • Why separate binaries and not one binary with cargo features: people install only what they want from Homebrew or Nix, there's no plugin ABI to maintain, and each binary stays around 2–5 MB because the shared kit is compiled in.
    • 
        
  • Dispatcher lookup order: next to itself, then NAME.app/Contents/Helpers, then $PATH.
    • 
        
  • Nix: the flake exports packages.{NAME,NAME-net,NAME-bt,NAME-sound}, an overlay, a home-manager module and a nix-darwin module: programs.NAME = { enable; modules = [ "net" "bt" "sound" ]; hotkeys = { … }; }. Your nix repo imports it as a flake input.
    • 
        
  • Later for others: a Homebrew tap (notarized cask for NAME.app, formulae per module), plus GitHub release binaries. Linux: Nix and cargo install first, AUR later.

      3. How every module runs
      
    
        
  • Loop: Elm style. Msg comes from keys, backend events or timers. update(&mut State, Msg) returns commands; view is a pure function of state.
    • 
        
  • Idle cost zero: it redraws only when a message arrives. A timer runs only while something animates (a spinner, the speedtest).
    • 
        
  • Runtime: tokio current_thread for the UI. Each native backend gets its own OS thread where the OS wants a run loop (CoreWLAN delegate, IOBluetooth notifications, the libpulse mainloop) and talks to the UI over channels.
    • 
        
  • Backends send snapshots: on any change the backend sends the whole small state (debounced ~30 ms), never deltas. Simpler and impossible to drift. This is the fix for "Bluetooth shows the wrong state".
    • 
        
  • Actions: every action is async with a typed error that maps to a toast message ("wrong password"). Pending state is per row, not global.
    • 
        
  • First frame under ~30 ms: draw the last known snapshot from ~/.cache/NAME/<module>.json immediately, then live data replaces it. The popup never opens empty.
    • 
        
  • Keys: crossterm EventStream. If the terminal supports the kitty keyboard protocol (SwiftTerm, Ghostty and kitty do), push DISAMBIGUATE_ESCAPE_CODES so Esc reacts instantly; otherwise fall back to the ESC timeout.
    • 
        
  • Esc rule: close the top dialog; with no dialog open, quit. Quitting closes the popup on both OSes.
    • 
        
  • Backend choice: enum dispatch (Real | Mock) so --mock works in release builds without boxing futures.
    • 
      

      
trait NetBackend {

      8. NAME.app, the macOS popup host
      
    
        
  • Size: about 400 lines of Swift plus SwiftTerm 1.19.0 (pinned). SwiftTerm compiles in one swiftc call with a one-line build-info stub (tested: 38 s, 2.6 MB). The build uses the Command Line Tools swiftc, the same way your panels build today; no SwiftPM.
    • 
        
  • Bundle: LSUIElement (no Dock icon). Info.plist carries the Location and Bluetooth usage strings; without them macOS silently denies the TUIs. Signed with your Developer ID; hardened runtime and notarization for public releases.
    • 
        
  • Why the permissions work: SwiftTerm starts the module with forkpty, so macOS treats NAME.app as responsible for it. One Location grant and one Bluetooth grant cover every module. verify
    • 
        
  • Window: borderless NSPanel subclass (canBecomeKey), level .popUpMenu, [.moveToActiveSpace, .fullScreenAuxiliary, .ignoresCycle]. Content is an NSGlassEffectView with radius 24 (NSVisualEffectView before macOS 26) holding the terminal view. Sized from font cell metrics to exactly 90×22 plus padding, centred on the screen under the mouse.
    • 
        
  • Dim: one borderless window per screen at 35% black, created once and reused. Clicking it closes the popup, so no Accessibility permission is needed.
    • 
        
  • Focus: remember the frontmost app → NSApp.activate() → makeKeyAndOrderFront → makeFirstResponder(terminal). On close: hide, kill the child, re-activate the previous app.
    • 
        
  • Toggle: the same hotkey while open closes it; a different module's hotkey swaps the content.
    • 
        
  • Hotkeys: Carbon RegisterEventHotKey needs no permission. Defaults ⌃⌥⌘N / ⌃⌥⌘B / ⌃⌥⌘M, configurable. macOS can't register fn hotkeys, so your skhd binds call NAME popup net instead.
    • 
        
  • IPC: Unix socket in ~/Library/Application Support/NAME/, one-line commands (toggle net, hide). Connect-first gives single-instance for free. It replaces the current IPCServer, which can freeze the UI (blocking accept, main.sync, no timeouts).
    • 
        
  • Start at login: an SMAppService toggle for vanilla users; a launchd agent from the home-manager module for you.
    • 
        
  • Location prompt: when Wi-Fi names are hidden, L in NAME-net asks the host to request Location. The host briefly becomes a regular app so the prompt is visible. verify
    •
